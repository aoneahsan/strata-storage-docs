## What this repo is

The **public** Docusaurus 3 documentation site for the `strata-storage` npm package — site only, no library
code. Live at **https://stratastorage-docs.aoneahsan.com**. Split out of the package repo on 2026-07-25
(was `strata-storage/docs-website` + the user-facing pages of `strata-storage/docs`).

- Sibling package checkout: `../strata-storage-public` · https://github.com/aoneahsan/strata-storage
- **Library bugs go to the package repo's queue** (`docs/REPORTED-ISSUES.md` there), never here. Those two
  issue files are deliberately NOT in this repo.
- **PUBLIC repo** — no secrets, no `.env`, no internal records. Governance in `CONTRIBUTING.md`
  (main protected; PR + 1 approval + green `build`; owner-only direct push).

## Main-Context + Skills + Model Workflow (IRON-SOLID — CRITICAL)

1. **NO default/built-in sub-agents** (`general-purpose`, `Explore`, `Plan`, `claude`, `fork`, …) for ANY work in
   this project — they cannot invoke /skills, which RULE #0 makes mandatory. Do ALL work (planning, implementation,
   review, exploration) in the MAIN context. A sub-agent is allowed ONLY when a CUSTOM agent exists in
   `.claude/agents/` for that exact job.
2. **Skills always:** before any task, scan the available-skills list and invoke EVERY relevant skill; if a needed
   skill is missing, download/enable/install it (or use the nearest installed equivalent and say so) — never
   proceed skill-less.
3. **Model workflow:** PLAN and REVIEW on **Fable 5**; EXECUTE the approved plan on **Opus 4.8**. Plans in
   `~/.claude/plans/`; multi-phase features keep a resumable tracker (`docs/features/<slug>/00-tracker.json`),
   resumed rather than re-planned from zero.

Global records (rules, policy, audit reports) live in the `ahsan-notebook` repo at
`static/assets/claude-code/`; the `~/.claude/…` paths are symlinks into it. Full text: `~/.claude/CLAUDE.md`.

## Working here

- **Gate:** `yarn build` — zero warnings. `onBrokenLinks` + `onBrokenMarkdownLinks` are `throw`, so
  **the build is the link checker**. Verify with `yarn build` / `yarn serve`, never a dev server.
- Sidebars are autogenerated from the `docs/` tree; a new category needs its `_category_.json` in the SAME
  change. Moved a URL? Add a redirect — never leave a 404.
- `static/llms-full.txt` is generated by `scripts/generate-llms-full.js`, which `yarn build` runs first.
  It is gitignored — never hand-edit.
- Content must match the real API in `../strata-storage-public/src`. No invented options or examples.

## Deploy

Push to `main` → `.github/workflows/deploy-docs.yml` (Node 24, Corepack Yarn 4) installs, builds, and
publishes `build/` to **GitHub Pages**. Custom domain pinned by `static/CNAME`. PRs run the `build` job
only, so it works as a required status check. Agents never commit, push, or deploy.
