# Contributing to strata-storage-docs

Thanks for helping improve the documentation for [strata-storage](https://www.npmjs.com/package/strata-storage). The live site is **https://stratastorage-docs.aoneahsan.com** — every merge to `main` deploys it automatically via GitHub Actions.

This repo holds the **documentation site only**. Bugs in the library itself belong in the package repo: [aoneahsan/strata-storage/issues](https://github.com/aoneahsan/strata-storage/issues).

## Governance

- `main` is protected by a repository ruleset: changes land through a **pull request with at least 1 approving review and a green `build` check**.
- Only the repository owner (**@aoneahsan**, repository admin) can push to `main` directly. Write-access collaborators still go through review — write access lets you push feature branches, nothing more.
- Force-pushes to and deletion of `main` are blocked for everyone.

## How to contribute

**Anyone (no access needed):** fork the repo, create a branch, commit, and open a pull request against `main`. The `build` check must pass and one approval is required.

**Want collaborator (write) access?** Open an issue using the **"Contributor access request"** template, or email aoneahsan@gmail.com, describing what you plan to work on. Access is granted at the owner's discretion and still cannot bypass review on `main`.

## Dev setup

```bash
yarn                # Yarn 4.x (yarn.lock is Berry format)
yarn start          # local dev server
yarn build          # the same gate CI runs
yarn serve          # serve the real production build
```

`onBrokenLinks` and `onBrokenMarkdownLinks` are both `throw`, so **the build is the link checker** — a broken link fails CI.

Notes:

- Markdown lives in `docs/`. Sidebars are autogenerated from the folder tree; ordering and category labels come from `_category_.json` files and per-page `sidebar_position` front matter.
- Content must match the real API in the [`strata-storage`](https://github.com/aoneahsan/strata-storage) source. No fabricated examples or invented options.
- `static/llms-full.txt` is generated by `scripts/generate-llms-full.js`, which `yarn build` runs first. Don't edit it by hand.

## Commit style

Conventional Commits (`docs: …`, `feat: …`, `fix: …`, `chore: …`). One commit per logical change.
